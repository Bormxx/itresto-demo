## API ENDPOINTS

### 8. POST /api/staff/consent

**Описание:**  
Сохранение согласия сотрудника на обработку персональных данных.

**Входные данные:**
```json
{
  "userId": "uuid",
  "consentText": "Полный текст согласия",
  "consentVersion": "1.0",
  "ipAddress": "192.168.1.1",
  "userAgent": "Mozilla/5.0..."
}
```

**Выходные данные:**
```json
{
  "success": true,
  "consentId": "uuid",
  "consentedAt": "2026-08-10T12:00:00Z"
}
```

**Таблица БД:** `staff_consents` (создать миграцию)
```sql
CREATE TABLE staff_consents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  consent_text TEXT NOT NULL,
  consent_version VARCHAR(10) NOT NULL,
  consented_at TIMESTAMP NOT NULL DEFAULT NOW(),
  ip_address VARCHAR(45),
  user_agent TEXT,
  revoked_at TIMESTAMP,
  revoke_reason TEXT
);
```

**Оценка:** 3 часа (endpoint + миграция + тесты)

### 9. DELETE /api/user/delete-account

**Описание:**  
Полное удаление персональных данных пользователя (реализация "права на забвение").

**Авторизация:** Требуется (только свой аккаунт)

**Входные данные:**
```json
{
  "confirmPassword": "текущий_пароль",
  "reason": "Причина удаления (опционально)"
}
```

**Логика:**
1. Проверка пароля
2. Логирование запроса (audit_logs)
3. Удаление персональных данных:
   - Анонимизация в таблице `users`: 
     - email → "deleted_<timestamp>@deleted.local"
     - phone → NULL
     - firstName/lastName → NULL
     - avatar → NULL
     - passwordHash → NULL
   - Сохранение только: id, restaurantId, role, deactivatedAt
4. Сохранение истории заказов (только суммы, без ПД)
5. Выход пользователя (invalidate session)

**Выходные данные:**
```json
{
  "success": true,
  "message": "Ваши персональные данные удалены"
}
```

**Оценка:** 4 часа

## АВТОМАТИЗАЦИЯ

### 12. Cron job: Автоматическая очистка старых данных

**Файл:** `scripts/cleanup-old-personal-data.ts` (создать)

**Описание:**  
Скрипт для автоматического удаления персональных данных по истечении срока хранения.

**Логика:**

**12.1. Сотрудники (деактивированные > 3 лет):**
```sql
UPDATE users
SET 
  email = 'deleted_' || id || '@deleted.local',
  phone = NULL,
  firstName = NULL,
  lastName = NULL,
  middleName = NULL,
  avatar = NULL,
  passwordHash = NULL,
  dateOfBirth = NULL
WHERE 
  isActive = false 
  AND deactivatedAt < NOW() - INTERVAL '3 years'
  AND email NOT LIKE 'deleted_%';
```

**12.2. Гости (не заказывали > 3 лет):**
```sql
-- Аналогично для гостей
WHERE role = 'guest'
  AND id NOT IN (
    SELECT DISTINCT clientId FROM orders 
    WHERE createdAt > NOW() - INTERVAL '3 years'
  );
```

**12.3. Владельцы заведений (договор расторгнут > 5 лет):**
```sql
-- Для владельцев ресторанов
WHERE restaurantId IN (
  SELECT id FROM restaurants 
  WHERE isActive = false 
    AND updatedAt < NOW() - INTERVAL '5 years'
);
```

**Запуск:** Cron job раз в месяц (1 числа в 03:00)

**Логирование:**
- Запись в `audit_logs` о каждом удалении
- Отчёт на email администратора: "Удалено X записей"

**Настройка cron:**
```bash
# В docker-compose.production.yml добавить сервис
cron-cleanup:
  image: node:20-alpine
  volumes:
    - ./scripts:/scripts
  command: node /scripts/cleanup-old-personal-data.ts
  environment:
    - DATABASE_URL=...
```

**Оценка:** 5 часов (скрипт + настройка cron + тестирование)
